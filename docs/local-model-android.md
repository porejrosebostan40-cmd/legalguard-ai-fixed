# Локальная модель на Android через Termux

Этот проект не содержит веса модели. Локальный режим работает с уже запущенным локальным сервером, совместимым с OpenAI Chat Completions API. Запросы в этом режиме разрешены только на `localhost`, `127.0.0.1` и `::1`; внешний адрес будет отклонён кодом приложения.

## 1. Подготовить Termux

В Termux установить инструменты сборки:

```bash
pkg update
pkg upgrade
pkg install git cmake clang make nodejs-lts
```

Собрать сервер llama.cpp:

```bash
git clone https://github.com/ggml-org/llama.cpp "$HOME/llama.cpp"
cmake -S "$HOME/llama.cpp" -B "$HOME/llama.cpp/build" -DGGML_OPENMP=ON -DGGML_NATIVE=OFF
cmake --build "$HOME/llama.cpp/build" --target llama-server -j 2
```

Сборка может занять продолжительное время и потребовать больше оперативной памяти, чем доступно на некоторых телефонах. Если сборка завершается из-за нехватки памяти, не увеличивайте число потоков.

## 2. Подготовить модель

Выберите совместимую с llama.cpp модель в формате GGUF из источника, которому доверяете. Для телефона с ограниченной памятью начинайте с небольшой квантизированной модели. Учитывайте, что небольшая модель может ошибаться в сложных юридических вопросах.

Создайте каталог и поместите файл модели туда:

```bash
mkdir -p "$HOME/models"
```

По умолчанию скрипт ожидает файл `$HOME/models/model.gguf`. Если файл называется иначе, передайте путь через переменную `MODEL_PATH`.

## 3. Запустить модель и интерфейс одной командой

После сборки llama.cpp и размещения GGUF-файла из каталога репозитория выполните:

```bash
bash scripts/start-legalguard-android.sh
```

Скрипт проверит зависимости и файл модели, запустит локальный сервер, дождётся ответа `/v1/models`, затем запустит интерфейс и выведет адрес `http://127.0.0.1:5173`. `Ctrl+C` остановит оба процесса. Журналы сохраняются в `~/.legalguard-ai/logs/`.

По умолчанию сервер слушает только `127.0.0.1:8080`, с контекстом 4096 токенов, двумя потоками CPU и API-именем `local-model`. Это исходные настройки для осторожного старта, а не гарантия производительности на конкретном устройстве.

Если модель не запускается из-за нехватки памяти, остановите её и выберите меньшую модель или уменьшите контекст через `CTX_SIZE`. Не открывайте сервер в локальную сеть или интернет.

Для ручного запуска компонентов по отдельности используйте `scripts/run-local-llama-server.sh` и команды `npm install` / `npm run dev -- --host 127.0.0.1`.

## 4. Настроить подключение в интерфейсе

В интерфейсе выберите **Локальная модель** и укажите:

- адрес: `http://127.0.0.1:8080/v1/chat/completions`
- имя модели: значение, поддерживаемое запущенным сервером. Для llama.cpp обычно подходит имя, которое он сообщает в своём API; если сервер не требует точного имени, можно оставить `local-model`.

Перед анализом нажмите **Проверить подключение**. Приложение проверит `GET /v1/models`, покажет доступность сервера и количество моделей, которые он сообщает. В поле имени модели по умолчанию стоит `local-model`, что соответствует алиасу в скрипте запуска.

Если браузер сообщает об ошибке CORS, проверьте параметр `--cors` у локального сервера. Не заменяйте адрес на публичный сервер. Открывайте интерфейс по локальному адресу Vite из Termux, а не через HTTPS-страницу на GitHub Pages: браузер может блокировать HTTP-запросы к localhost как смешанный контент.

## Ограничения

- Проверена сборка приложения, но запуск llama.cpp и конкретной модели на вашем телефоне не подтверждён.
- Локальный режим не отправляет запросы в облачные API, но сам файл модели нужно получить отдельно.
- Сканированные PDF и изображения требуют OCR; текущая версия принимает текст, а не распознаёт сканы.
- Автоматическая проверка цитат проверяет наличие текста в исходном материале, но не доказывает правильность юридического вывода.
- Все сформированные жалобы остаются черновиками. Перед использованием проверяйте первоисточник, действующие нормы, судебную практику, сроки и процессуальную форму.
