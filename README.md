# LegalGuard AI — карманный помощник для работы с судебными материалами

MVP для контролируемого анализа судебных актов и подготовки черновиков апелляционных и кассационных жалоб.

## Текущее состояние

- Интерфейс React + TypeScript.
- Импорт судебного текста из TXT.
- Тестовый провайдер с демонстрационными результатами.
- HTTP-адаптер для внешнего серверного контура: `/api/deepseek/analyze` и `/api/chatgpt/arbitrate`. Серверная реализация этих маршрутов в этом репозитории пока не включена.
- Сборка проекта не требует API-ключей.
- Результат всегда считается черновиком: прохождение структурного контроля не означает юридическую точность или готовность к подаче.

## Архитектура конвейера

Судебный материал → первичный анализ → арбитраж находок → стратегия → структурный контроль → черновик.

Провайдеры отделены от юридического ядра через интерфейс `AIProviderSet`. Это позволяет подключить локальные модели без переписывания логики конвейера. **Запуск локальной модели пока не реализован**; тестовый провайдер использует демонстрационные данные, а HTTP-провайдер ожидает серверные маршруты.

## Жёсткие инварианты

- Отклонённое основание не попадает в стратегию.
- `pending` и `needs_review` блокируют прохождение структурного контроля.
- Неизвестные и повторяющиеся идентификаторы оснований блокируют контроль.
- Секретные ключи не должны попадать в браузерный код.
- Успешная сборка и структурный контроль не являются юридическим заключением.
- Перед использованием черновика человек обязан проверить цитаты по первоисточнику, фактические выводы, действующие нормы, сроки и процессуальные требования.

## Локальная разработка

Требуется Node.js 20 или совместимая актуальная версия.

```bash
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
```

GitHub Actions выполняет только установку зависимостей и сборку. Доступ к облачным API и платные секреты для CI не нужны.
